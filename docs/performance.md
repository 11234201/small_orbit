## 2026-11-10：数据模型性能与旧格式兼容性

## 范围和方法

这是合成数据模型基准，不是 Android/Windows 启动、界面帧率、后台耗电或终端用户等待时间的测量。基线是本轮修改前的 task_model.dart（与首提交 f58dc8e 的模型一致）；优化版保留原持久化格式 1。

环境：mfs-remote，Linux x86_64，Intel Xeon Gold 6248R @ 3.00 GHz，Dart 3.13.7。两版均以 dart compile exe 编译为 AOT 可执行文件，taskset 固定在 CPU 95；服务器不是专用隔离硬件。每版运行两个独立进程，每个操作先预热 3 次，再测 7 组，以下为全部 14 组的中位数。每组热态 materialize/active 各 20 次，history 5 次，decode 3 次。

日期固定 2026-11-10；重复任务从 2021-01-01 每日开始，标题和任务数据为生成样本，不含用户数据。空清单、100 任务（10 个重复）、1000 任务（25 个重复）、100 个多年重复任务共四种负载。后者有 213,900 条历史，未超过格式的总记录上限。

最大历史样本的 14 组范围：热态补全 1037.91–1075.32 → 1.29–1.36 ms；历史查询 1175.14–1207.70 → 32.69–35.41 ms；解码 1306.28–1339.01 → 231.10–236.16 ms。

## 改动和兼容性

1. 为不可变任务历史增加只存在内存中的覆盖边界。同一日期反复检查直接返回；向前只补新周期。修改起始日、重复规则或历史会失效；回拨时间不删历史。缓存不进入 JSON，旧文件不需要迁移字段。
2. 最近历史查询先用已校验的 YYYY-MM-DD 键筛选窗口，再解析窗口内的日期和完成时间，避免每次解析全部旧历史。
3. 历史键仅需检查公历日期合法性，改用闰年/月天数验证，避免逐条构造当前时区的 DateTime。任务实际日期仍走 parseDay；历史日期标签的合法性不再依赖当前时区，适合跨设备备份。
4. OrbitDocument.materialize 在没有数据改变时不复制整份任务列表。

固定种子 271828 的旧/新模型对照：250 场景、5000 步，包含漏做/已完成、前后拨时间、编辑开始日期/每周规则、删改历史、标题编辑，序列化业务内容和历史查询均相同。四次基准结果校验和均为 520770。

新增 5 项 Flutter 回归（由主代理统一执行）：历史日期闰年/范围；重复运行和时间回拨；规则/历史修改使覆盖缓存失效；历史窗口边界与单次任务本地完成日；原格式1文件加载、补历史、保留旧副本、导出和重开无字段损失。没有模拟覆盖安装等同真机升级的结论。

## Windows 10 发布版启动与隐藏资源

本机 Windows 10 build 19045，16 个逻辑处理器；1.0.0-rc.1 release，0/100/1000个无提醒合成任务，各3次普通启动，系统文件缓存未清空。独立 `.qa_data/windows_probe_*` 目录，隐藏窗口，不读取个人数据。Windows原生能力无法在Linux上替代，因此这一步在本机执行；没有在本机执行模型基准或完整Flutter测试。

首次对照暴露了真实问题：隐藏启动不会自动传递为 Flutter 的隐藏生命周期，泡泡仍执行开场动画。修复后原生窗口可见性通过 WindowService 接入 TickerMode，最小化/收起不影响提醒而停止动效。相同样本在检测到首帧文件后第2–4秒采样：

| 任务数 | 隐藏CPU：修复前→后中位数（单核百分比） | 修复后范围 | 工作集中位数 MiB | 启动至检测首帧文件中位数 ms |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 1.553 → 0.775 | 0–1.558 | 159.70 | 1995.83 |
| 100 | 32.627 → 0.779 | 0.777–1.556 | 172.37 | 1980.17 |
| 1000 | 31.917 → 1.562 | 0–4.682 | 175.41 | 2023.11 |

这描述隐藏启动后采样区间，不等于长期空闲、电量或可见动画成本。CPU口径为进程累计CPU时间/墙钟时间，一整核为100%，不是整机CPU百分比。Flutter数据初始化至首帧回调约20–35ms，但进程创建和原生引擎启动仍包含在约2秒总启动检测时间中，不能仅用Dart时长宣传启动速度。

探针原始记录：`logs/windows_probe_before_visibility.json`、`logs/windows_probe_after_visibility_3runs.json`。第二份记录新增的 `markerTimestampMs` 曾因 PowerShell 7.5 自动将JSON日期转为UTC对象后被再次按本地字符串解析，出现约负8小时偏差；该字段废弃，不用于上述结果，其它单调时钟/CPU/内存字段不受影响。修正后按每种任务数再跑1次，记录于 `logs/windows_probe_1.0.0-rc.1.json`，UTC首帧信号耗时为2051.27/2002.27/2034.95ms，并保留起止UTC供核对。

共21次探针运行（9次修复前、9次修复后、3次时钟核对）均由应用自己的退出握手正常结束，退出码0；没有遗留测试进程。该证据覆盖启动和安全退出链路，不替代托盘点击、系统通知送达、Windows 11或双屏端到端验收。
