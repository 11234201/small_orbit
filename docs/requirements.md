## 2. 产品定义建议

一个随手记录、轻松完成的待办工具：任务以更灵动的形态呈现，完成时通过可感知的消除反馈离开当前视图，完成记录保留。

核心路径：打开工具 → 输入任务 → 保存 → 查看任务 → 点选或手势完成 → 必要时撤销。泡泡点破、纸片收纳、卡牌划走或点击完成；三种展示共用同一份任务。

“轻量”分成三个可独立评估的维度：

- 使用负担：输入任务需要几步、是否强制填写日期或分类、主界面信息量。
- 响应速度：冷启动、唤起窗口、保存和勾选的等待时间。
- 资源消耗：发布包大小、安装后占用、空闲内存和后台功耗。

用户已明确优先使用负担与响应速度。资源消耗作为实测约束，不以极小包体为首要目标，也不承诺未经测量的数值。

### 交互建议（待界面评审）

- 用户已选择三种展示全部保留，首次打开默认泡泡。建议在界面中提供展示选择器，并在本机记住上次选择；切换不修改任务内容、日期、提醒、重复规则或完成状态。
- 泡泡大小先采用重要度与紧急度各三档、等权组合的草图规则，越重要或越紧急越大，同时最高时最大。三档与映射属于实现建议，用户已确认的是大小表达这两个维度。
- 三种运动节奏均可选。草图先采用“开场弹一阵后安静”作为默认，默认节奏尚未由用户特别指定；建议在本机记住选择，并提供暂停/继续。
- 泡泡互相碰撞、碰边界反弹；鼠标悬停、键盘聚焦或按下时暂时固定相应泡泡，以便点选。物理运动不改变任务数据。
- “今天 / 全部”仍作为任务范围的候选入口，不要求使用条列展示。已完成记录收起，消除表示完成当前任务或当前期，不表示删除数据。
- 直接输入文字即可新增，日期、提醒时间、重复规则均可选，放在需要时展开的区域。
- “日期”与“提醒时间”分开：只有日期的任务不默认在零点提醒。
- 重复支持每天、每周；新周期按计划正常出现，漏做的旧期记录为未完成，不堆积到当前清单。每周星期选择等控件细节待界面评审。
- Windows 小窗口建议记住尺寸与位置，默认收起到任务栏；关闭窗口后的提醒作为需要验证的产品目标。
- 同一清单的操作在两端保持一致，Windows 支持回车保存和键盘切换，Android 采用适合触屏的点击区域。

## 4. 离线导入导出与恢复

用户已确认：两端独立离线使用；手动导入采用整份恢复，并在替换前自动备份当前数据。

- 建议用 JSON 保留任务 ID、文字、日期、提醒时间、重复规则、每期完成记录和格式版本。
- 导入文件中的任务数据替换本机任务数据，不与本机独有任务合并。
- 建议流程：选择文件 → 校验格式和数据 → 预览将恢复的内容 → 用户执行恢复 → 自动备份当前数据 → 完整替换 → 重新安排提醒。
- 自动备份失败时中止替换；无效文件不改变现有数据；恢复失败应能回退原有数据。
- 建议提供“恢复上次导入前的备份”入口，并展示备份时间。
- 文件包含重复规则和历史记录；备份不携带设备通知权限或系统通知队列，导入后按本机能力重建提醒。
- 上述失败处理和文件格式属于实现建议，备份保留数量与存放位置在技术设计时明确。

## 5. 重复任务的已确认行为

- 例：设置每天 20:00 读书。11 月 10 日未完成，11 月 11 日仍正常出现当天的读书任务。
- 11 月 10 日记为“未完成”，保留历史记录，但不会作为另一条待办堆在 11 月 11 日的清单中。
- 完成当天任务只完成当期，下一期继续按原计划出现。
- 每周任务同样按计划周期推进，漏做旧期不阻止下一期出现。

建议补充：离线关闭数日后再次打开，也应根据日期计算当前期并保留旧期状态；提醒时间到达不立即将任务记为漏做，具体期末边界按日历规则设计。历史补做是否开放后续再定，不增加首版主流程操作。

## 7. 验收建议（尚未由用户确认）

- 新增任务仅强制输入文字；保存入口直接可见。
- 断网可新增、修改和完成任务；已保存任务重启后仍存在。
- 完成操作立即反馈，动效不会阻止继续操作，误勾可撤销。
- 消除只完成任务或重复任务的当前期；已完成数据可查看、导出与恢复。撤销后任务回到当前视图。
- 首次打开默认泡泡，选择纸片或卡牌后可记住本机偏好；跨模式切换不改变任务数量、状态、日期、重复规则与撤销结果。
- 非条列展示仍需清晰展示任务文字与提醒信息；三种模式分别验证任务多、文字长和窄窗口的情形。
- 同一窗口条件下，提高重要度或紧急度不得使泡泡变小；运动中保持可点击、边界内显示，暂停时位置稳定。
- 三种运动节奏行为可区分：开场后停止、持续缓漂、持续活泼；选择可记忆，页面隐藏或减少动态效果模式下暂停运动。
- 用包含中文、换行和完成状态的样例，在 Android 导出并在 Windows 导入，反向也成立。
- 无效文件导入失败时，现有任务保持完整。
- 导入前备份失败时不替换数据；导入成功后可恢复到导入前的任务数据，重复规则和历史记录均保留。
- 完成一次重复任务只影响本次，后续按原计划推进；撤销不会制造重复条目。
- 连续漏做三天的每日任务，当前期只出现一条待办，过去三期保留未完成记录；应用关闭后重新打开也满足此行为。
- 改期、完成和删除任务后，对应提醒取消或更新；导入后提醒与任务一致。
- 提醒验证覆盖窗口收起/关闭、应用重启、设备重启、权限拒绝、休眠与时区变化，并记录不能保证送达的系统条件。
- 确定参考设备后，使用发布构建记录启动、内存和包体基线，再制定数值目标。
