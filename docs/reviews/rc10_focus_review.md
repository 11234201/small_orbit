## 已确认并修复

以下为本轮六处 P2 问题，路径相对 `src/small_orbit/`。

| 问题与触发条件 | 原行为 | 修复 |
| --- | --- | --- |
| 专注开始保存期间，任务已删除/完成或整份备份已替换 | 校验发生在写入前；写入期间控制器尚看不到新会话，可能漏掉取消，留下失效的运行会话 | `platform/focus_service.dart` 在落盘后、启动计时/原生同步前重新检查目标及恢复代次，失效会话持久化为已结束 |
| 重开时旧专注已过期，而且目标已不存在 | 先改成 finished，随后仅检查 ongoing，会绕过目标失效判断 | 恢复也经过同一校验，已失效目标不会发布完成状态或补发提示 |
| 已结束一段专注后选另一件事 | 新任务沿用旧会话的 0:00 和“这一段结束了” | `ui/playground_panel.dart` 只对匹配目标展示旧完成状态；新目标展示新时长和“准备开始”；保留失效运行会话的结束重试入口 |
| 切换到抽中任务时，结束当前专注的保存失败 | 通用操作函数吞掉错误，调用方仍切页/替换选择 | 操作函数返回成功状态，失败或忙碌时中止后续切换，留在原页面并提示 |
| Android 通知被权限/渠道阻止，随后专注变为 finished | 重试入口只接收 running，后续权限恢复也不会尝试未送达的完成提示 | `focus_plan.kt` 提供调度决策，`focus_scheduler.kt` 对已到期、未送达的 finished 会话也尝试通知；成功回执仍防止重复，暂停/结束不重发 |
| Windows 专注结束通知失败或应用重开 | 完成时只尝试一次；重试只同步状态，缺少跨进程提示回执 | 本机 `focus.json` 保存已提示会话 ID；恢复/重试会补发，已送达只重试回执保存。回执写入失败会阻止退出并允许重试；目标完成/删除后取消待补发状态 |

Windows 平台调用增加可注入的平台选择，运行时仍按真实操作系统确定行为，便于 Linux 上模拟桥接成功/失败。未把完成任务与专注到点合并：到点仍由用户决定是否完成任务。
