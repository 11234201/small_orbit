# 小事星球后续开发路线

更新：2026-11-10（Asia/Shanghai）。这是基于当前交付和用户偏好的建议顺序，版本号用于划分里程碑，不表示所有候选功能均已确认，也不预设交付日期。

## 起点：0.1.0 离线预览版

已交付 Windows 便携包和 Android APK。默认泡泡，纸片和牌堆可选；包含运动节奏、重要/紧急大小映射、日期提醒、每日/每周重复、历史、撤销和手动备份恢复。17 项 Flutter 测试、5 项 Android 日历调度测试及包完整性检查通过。

尚缺的是 Android 15 真机后台提醒、Windows 10/11 托盘和系统通知的端到端验收，以及真实设备上的启动、内存和耗电测量。自动测试通过不等于这些系统行为已经验证。证据见 [验证记录](validation.md)。

后续以“操作简单、打开快、有轻巧的完成反馈”为判断标准；保持独立离线、三种展示共用数据、导入前自动备份。每个阶段完成验收再进入下一阶段。

## 第一阶段：0.1.1，日常使用可靠

优先级最高。先在用户实际使用的 Android 15、Windows 10 和 11 上验证，再修复发现的问题。

| 场景 | 要做的工作 | 通过条件 |
| --- | --- | --- |
| Android 提醒 | 测试通知拒绝后重新允许、准时提醒权限、后台/锁屏、省电、重启和时区变化；检查改期、完成、删除后取消旧提醒 | 在允许提醒的正常设备条件下按约定工作；系统限制导致的延迟或抑制可解释，权限状态显示准确 |
| Windows 小窗口 | 测试关闭到托盘、重新唤起、最小化、重复打开、明确退出、休眠恢复及勿扰模式 | 收起可恢复、数据不丢；运行中正常提醒，退出后的边界与说明一致，无重复进程覆盖数据 |
| 两端文件往返 | Android 导出到 Windows 恢复，反向再做一次；包含中文、长标题、重复规则和历史；验证自动备份回退 | 两端数据一致；损坏文件和备份失败不替换现有数据；恢复后提醒与当前任务一致 |
| 连续使用 | 用少量真实工作/生活任务连续试用约一周，记录实际卡点与设备条件 | 无数据丢失、漏做堆积和无法恢复的问题；已发现的阻断性问题修复并回归 |

产物：修复版安装包、两端实测记录、更新后的已知限制。手机后台送达需接触实际设备才能验收，现有模拟/逻辑测试不能代替。

## 第二阶段：0.2，交互更顺手、更有趣

沿用当前三种展示，先完善它们的手感。

- 泡泡：调整开场力度、碰撞和停止节奏；改善长标题、点击区域及重要/紧急辨识，避免为了完成任务追着泡泡点。
- 完成反馈：打磨气泡消除、纸片收纳和卡牌划出的短动效；保持撤销容易找到，不增加确认步骤。
- 多任务与小屏：优化分组、概览、编辑入口和键盘弹出后的布局；减少动态效果时同样可用。
- Windows：记住窗口尺寸和位置；全局唤起快捷键作为可关闭的候选项，实施时再确定按键和冲突处理。

通过条件：常用操作比 0.1.1 更顺手；快速新增仍只需输入标题；三种模式共用状态和撤销；动效不阻塞操作，用户试用反馈认可。暂不加入养成、积分或复杂游戏机制。

## 第三阶段：0.3，速度、资源和升级

- 在固定设备和固定任务样本上记录冷启动、窗口唤起、保存耗时、空闲内存和后台 CPU/耗电；先建立基线，再针对实际瓶颈优化，不预先承诺数字。
- 核对暂停、减少动态效果、切换视图和窗口不可见时的绘制行为，减少无用计算，同时保留必要提醒。
- 按设备需要提供更小的 Android 架构专用包；保留简单的 Windows 安装/启动入口。
- 验证覆盖升级、数据格式迁移和回退备份；保管 Android 签名密钥，确保后续版本能更新安装。
- 整理统一的版本号、测试、构建和校验脚本。之后如接入 CI，再确定托管位置和权限。

通过条件：性能变化有同设备的前后测量；升级保留任务与历史；干净环境可按文档重建安装包；发现的问题有必要的回归检查。

## 第四阶段：1.0，稳定的个人离线工具

通过连续使用和两端验收后确定稳定版。新增功能由真实使用频率决定：任务多时再考虑搜索或轻分类，经常快速记录时再考虑 Android 快捷入口、Windows 置顶等。

账号、云同步、协作和复杂项目管理不进入当前优先路线。如以后确实需要自动同步，单独讨论隐私、离线冲突、重复任务和恢复语义，不直接把手动“整份替换”当作同步机制。

## 开发和版本管理

- 当前离线版作为本地 Git 首个可回溯版本，后续按问题或小功能独立提交，保留清楚的修改目的和验证结果。
- 源码、文档、必要图标与预览、依赖锁文件进入 Git；安装包、工具链、缓存、日志、用户数据与签名材料通过 `.gitignore` 排除。
- 默认延续现有 Flutter 工程。构建和逻辑测试优先在 `mfs-remote`，Windows 原生编译与窗口验收在 Windows。
- 每轮交付同步更新版本、使用说明、验证记录和已知问题；不把尚未完成的真机验证写成已通过。

近期建议直接进入第一阶段。历史调研与原型记录已归档到 [prototype_history.md](prototype_history.md)。
